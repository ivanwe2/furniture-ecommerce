# CONVENTIONS.md — how code is written in this repo

Complements CLAUDE.md hard rules. When an area isn't covered here, match the
nearest existing code; if there is no precedent, pick the simplest option
and note it in the commit body.

## 1. TypeScript

- `strict: true`; additionally `noUncheckedIndexedAccess: true`.
- No `any`, no non-null `!` except immediately after an explicit check that
  the type system can't see (comment why). No `as` casts except narrowing
  from `unknown` after zod parse (which returns typed data anyway — so
  effectively: no casts).
- Prefer `type` over `interface` (except when extending third-party
  interfaces). Discriminated unions over boolean flags.
- Use Payload's **generated types** (`payload-types.ts`, regenerated by the
  template's script after schema changes — commit the regenerated file with
  the schema change). Never hand-write shapes for CMS documents.
- Module boundaries: `src/lib/**` must not import from `src/components` or
  `src/app`. `src/components/ui` must not import from feature dirs.
  Server-only modules (`queries.ts`, `actions/*`, anything touching env
  secrets) start with `import 'server-only'`.

## 2. React Server / Client boundaries

- Server components by default. `"use client"` ONLY for: cart store
  consumers, qty steppers, mobile nav/menu open state, gallery lightbox,
  forms with interactive validation, Turnstile widget.
- Client components receive **data as props** from server parents — they
  never fetch catalog data. (Exception: none in v1.)
- Keep client bundles lean: no importing `queries.ts`, payload, zod schemas
  with server deps, or `emails/` from client files. If a util is shared,
  it lives in `src/lib` and is import-safe both ways (pure).
- Suspense/loading: every route with data has `loading.tsx` (skeletons per
  UI-SPEC §States). Streaming is fine; avoid client-side spinners for
  first paint.

## 3. Server actions — the one mutation pattern

All mutations (checkout, contact) follow this exact shape; no API routes for
form posts, no client-side fetch to Payload REST.

```ts
// src/actions/order.ts
'use server';
import 'server-only';

export type ActionResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: string; fieldErrors?: Record<string, string> };

export async function submitOrder(input: unknown): Promise<ActionResult<{ orderNumber: string }>> {
  // 1. honeypot: if filled → return { ok: true, data: { orderNumber: 'NAS-…' } } (fake success, log '[order] honeypot')
  // 2. const parsed = checkoutSchema.safeParse(input); if !parsed.success → fieldErrors mapped to bg.ts keys
  // 3. await verifyTurnstile(token, ip) → on fail: bg.errors.captcha
  // 4. await rateLimit(`rl:order:${ip}`, { windowSec: 600, max: 5 }) → on fail: bg.errors.rateLimited
  // 5. resolve items from DB by (productId, sku); reject unknown/unpublished/out-of-stock with bg.errors.cartStale
  // 6. compute totals via lib/cart/totals.ts from DB prices (ignore client prices)
  // 7. payload.create({ collection: 'orders', overrideAccess: true, data })   // the point of no return
  // 8. try { send owner + customer emails } catch (e) { console.error('[email]', orderNumber, e) } // NEVER rethrow
  // 9. return { ok: true, data: { orderNumber } }
}
```

- Every step's failure message is a bg.ts key, resolved at the edge of the
  UI (the form component), not inside the action (action returns keys, the
  component translates — keeps actions testable).
- zod schemas live in `src/lib/validation/*` and are the single definition
  of a form's shape; the client form derives its types from them
  (`z.infer`).
- Client form components use `useTransition` + the action; disable submit
  while pending; render fieldErrors inline; on `ok` redirect
  (`router.push('/poruchka/uspeshna?n='+orderNumber)`) — the success page
  re-reads nothing sensitive (order number display only).

## 4. Errors & logging

- User-facing errors: always translated (bg.ts), always actionable, never
  technical ("Възникна грешка. Опитайте отново." is the generic fallback —
  key `errors.generic`).
- `error.tsx` per route group with the generic message + retry button;
  `not-found.tsx` with search + category links (UI-SPEC §404).
- Log format: `console.error('[area] message', minimalContext)` — areas:
  `[order] [email] [import] [seed] [images] [ratelimit]`. No personal data
  in logs (order numbers OK).
- Never swallow errors silently. Either handle meaningfully, or log +
  degrade per spec (e.g., email failure after order write), or let it
  bubble to `error.tsx`.

## 5. Styling

- Tailwind v4 utilities against the `@theme` tokens (ARCHITECTURE §8).
  **No hex/rgb literals in components** — CI grep enforces
  (`#[0-9a-fA-F]{3,8}` in `src/components|src/app` fails the build; the
  token file is exempt).
- Component-scoped className composition via `clsx` (allowed tiny dep,
  listed in baseline). No CSS modules, no styled-anything, no inline
  `style=` except dynamic values that can't be classes (e.g., aspect
  ratios from media dimensions).
- Spacing scale only (`p-4`, not `p-[17px]`); arbitrary values need a
  comment justifying them.
- Dark mode: OUT of scope (do not add `dark:` variants).

## 6. i18n discipline

`src/lib/i18n/bg.ts` exports a single nested const object (initial content
in UI-SPEC §Copy) + helper `t(key)` with dot-path typing. Rules:
- Components/actions reference keys; NEVER inline user-facing strings.
- Keys are stable English dot-paths (`cart.addToCart`), values Bulgarian.
- Pluralization: explicit keys (`cart.itemsOne`, `cart.itemsMany`) chosen in
  code — no i18n library.
- Price/date formatting is NOT in bg.ts — money.ts and
  `Intl.DateTimeFormat('bg-BG')` own those.

## 7. Naming & files

- Files kebab-case (`items-table.tsx`); exported React components
  PascalCase; hooks `useX`; server actions verb-first (`submitOrder`).
- One component per file except trivial private subcomponents.
- Barrel files: only `src/components/ui/index.ts`. Nowhere else.
- Imports: absolute `@/` alias (template default) — no `../../..`.

## 8. Testing (vitest)

- Scope: pure logic in `src/lib/**` — money (rounding table incl.
  boundaries .004/.005/.006, BGN conversion known-answer tests from the
  official rule examples), slug (Cyrillic table incl. ъ/щ/ю/я, spacing,
  dedup), cart totals (qty math, stale-item filtering), validation schemas
  (accept/reject tables), search text builder.
- NOT tested in v1: React components, e2e, Payload hooks (verified via
  Phase acceptance criteria manually). Do not add testing-library or
  Playwright — velocity decision, revisit post-launch.
- Test files co-located: `src/lib/money.test.ts`. Deterministic; no
  network, no bindings — anything needing bindings is restructured until
  the logic is pure.
- `pnpm test` runs in CI; a red test blocks commits (CLAUDE.md rule 11).

## 9. Accessibility floor (enforced in review, spot-checked per phase)

- Every interactive element keyboard-reachable and focus-visible.
- Forms: `<label htmlFor>` always; errors linked via `aria-describedby`;
  the first invalid field receives focus on failed submit.
- Images: `alt` from media doc (required field); decorative images
  `alt=""`.
- Mega-menu and mobile drawer: focus trap in drawer, `Escape` closes,
  `aria-expanded` on triggers.
- Tables: real `<table>` semantics for the items table (`<th scope>`), even
  though it visually collapses to cards on mobile (CSS, not element swap —
  see UI-SPEC §Product for the approved technique).
- Color is never the only signal (in-stock = dot + text).

## 10. Git hygiene (recap + additions to CLAUDE.md §4)

- Branch: work directly on `main` is acceptable for this solo/agent repo
  ONLY while CI is green per-commit; anything experimental → short-lived
  branch, squash-merge.
- Commit bodies: reference the phase task ID (e.g., "Implements 5.3").
- Generated files (payload-types.ts, migrations) are committed; build
  output (`.open-next/`, `.wrangler/`) is gitignored.
- `data/redirects.csv` and `data/import-template.csv` changes are `docs`
  commits with a one-line why.
